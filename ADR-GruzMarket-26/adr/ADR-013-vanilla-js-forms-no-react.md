# ADR-013: Vanilla JS формы вместо React island

**Status:** Accepted · 2026-10-01 · Refines: ADR-001

## Context
ADR-001 допускает React-острова для «формы заявки, калькулятора смены». При
реализации формы встал выбор: React (как ADR-001 намекает) или чистый JS.

Что форма реально делает:
- Валидирует телефон (≥10 цифр).
- Отправляет FormData через fetch в Cloudflare Worker (или открывает WhatsApp
  с prefilled текстом как фолбэк, ADR-008).
- Показывает/прячет .form-ok / .form-err.

Сравнение:
| | React island | Vanilla `<script>` |
|---|---|---|
| JS в бандле | +40 KB (React + runtime) | ~1 KB inline |
| Hydration | 50-100ms | 0 |
| Code volume | ~80 строк JSX+hooks | ~35 строк JS |
| TypeScript | да | да (через `<script>`) |

Для одной формы с 4 полями + submit — React избыточен.

## Decision
Форма — vanilla JS в `<script>` блоке `LeadForm.astro`. Все обработчики
навешиваются `querySelectorAll('.lead-form').forEach(...)`, работает для
нескольких экземпляров формы на странице (hero + подвал — две формы).

React-острова оставляем в арсенале для **калькулятора смены** (сложная
логика с несколькими полями, пересчётом, валидацией диапазонов) — когда
решим его делать. Сейчас калькулятор на главной — не нужен (hero с формой
даёт лучшую конверсию, см. BACKLOG).

## Consequences
**Плюсы:**
- 0 KB хидратации, Lighthouse Performance не страдает.
- Нет зависимости React в package.json — bundle остаётся crystal clean.
- Один файл компонента, markup + стили + поведение рядом (как в Vue SFC).

**Минусы:**
- Если форма разрастётся (мультистеп, динамические поля, валидация полей
  друг от друга) — переписать на React будет болезненно. На текущей форме
  такого роста не предвидим; при необходимости отдельный ADR на миграцию.
- `import.meta.env.PUBLIC_LEAD_ENDPOINT` обрабатывается vite'ом как замена
  строки при сборке — работает, но менее очевидно чем в React (`process.env`
  с precompile).
