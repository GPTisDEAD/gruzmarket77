# ADR-010: Аналитика и внешние сервисы через переменные окружения

**Status:** Accepted · 2026-10-01

## Context
Сайт собирается ассистентом **до** того, как Артём создаёт счётчик Я.Метрики
(нужен его аккаунт), деплоит Cloudflare Worker (нужны ключи), подключает домен.
Нельзя хардкодить айди/URL в код — ассистент их просто не знает.

Варианты:
- **A. Хардкод в код + коммит после получения** — коммит ради одного числа,
  рассинхрон между выдачей значения и сборкой.
- **B. Env-переменные, задаются в GitHub Actions / Cloudflare — выбран.**

## Decision
Все внешние интеграции сайта управляются **`PUBLIC_*`-переменными сборки
Astro** (vite). Паттерн: если переменная не задана — компонент не рендерит
ничего (ноль веса на странице), не ломает сборку, не кидает ошибки.

Реестр:

| Переменная | Назначение | Компонент | Что без неё |
|---|---|---|---|
| `PUBLIC_YM_ID` | Номер счётчика Я.Метрики | `Analytics.astro` | Счётчик не грузится |
| `PUBLIC_LEAD_ENDPOINT` | URL Cloudflare Worker | `LeadForm.astro` | Форма через WhatsApp (ADR-008) |
| `PUBLIC_GTM_ID` | GTM (будущее) | — | — |

**Задание на деплое:** в `.github/workflows/deploy.yml` перед `npm run build`
добавляется шаг с env. Пример для метрики:
```yaml
- run: npm run build
  env:
    PUBLIC_YM_ID: ${{ vars.PUBLIC_YM_ID }}
    PUBLIC_LEAD_ENDPOINT: ${{ vars.PUBLIC_LEAD_ENDPOINT }}
```
Значения хранятся в **GitHub repo variables** (не secrets — они нужны в HTML,
клиентскую сторону всё равно видно).

**Секреты, которые НЕ в сайт**, а только в сервере — токен бота, Google-ключ —
живут исключительно в Cloudflare Worker Secrets, не в репе, не в GH Actions.

## Consequences
**Плюсы:**
- Ассистент пишет код один раз, без «а вот сюда вставить номер».
- Включение фичи = Артём добавляет variable в GitHub Settings → Secrets and
  variables → Actions → Variables → New variable. Два клика, без изменения кода.
- Fail-safe: отсутствие переменной не ломает сборку.

**Минусы:**
- При добавлении нового PUBLIC_*-канала надо помнить обновить workflow
  (env в build step). Решение: держать список env в этом ADR, в CANON §13
  — чеклист при добавлении.
